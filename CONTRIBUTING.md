# New contributor guide

## Installation

TrustyAIService uses `uv` as a package manager. To install it, follow the official [installation guide](https://github.com/astral-sh/uv).

Then install the project with every dependency group and the optional backends
used by CI:

```bash
make sync

```

This runs `uv sync --all-groups --extra mariadb --extra postgres --extra sqlite
--extra migration --extra mmd`.

`uv` installs only the default `dev` group on its own. `pytest` and its plugins
live in the `test` dependency group, so a bare `uv run pytest` fails with
`unrecognized arguments: --dist=loadgroup -n`.

## Testing

```bash
make test

```

This runs the suite without `tests/service/data/migrations`, then runs that
suite serially with `-n 0`, matching CI. It leaves out the PostgreSQL driver so
those storage tests skip without a server. Use `make test-databases` (whole
suite) or `make migration-test` (migration suite, serial) when the live database
gates are required; both install the driver and set
`TRUSTYAI_REQUIRE_LIVE_SQL_TESTS=1` so skips become failures.

Live SQL tests require PostgreSQL and MariaDB. Start them, then run the gated
suite:

```bash
podman compose -f tests/resources/compose-local-postgres.yaml up -d --wait
podman compose -f tests/resources/compose-local-maria.yaml up -d --wait
make test-databases
make migration-test

```

## Dependencies

`requirements.txt` (runtime, hashed, installed by `Containerfile`) and
`requirements-build.txt` (build backend, hashed) are generated by uv. Regenerate
them with the make targets rather than editing by hand:

```bash
make requirements        # uv export --frozen from uv.lock; deterministic
make requirements-build  # recompiles requirements-build.in; bumps unpinned deps

```

`make deps` performs the whole refresh: `uv lock --upgrade`, then both files.
Run `uv lock` first if `pyproject.toml` changed, because the export uses
`--frozen`. `requirements-build.in` is intentionally unpinned, so expect version
bumps there. The container installs both files with `pip --require-hashes`, so
rebuild and test the image after regenerating either file.

## pre-commit

In order to ensure proper and consistent code formatting, we use `pre-commit` in combination with tools like `ruff`, `flake8`, and `mypy`. When committing your code, make sure that all the pre-commit checks pass in your local environment.
To install pre-commit:

```bash
pre-commit install -t pre-commit -t commit-msg

```

Run manually pre-commit:

```bash
pre-commit run --all-files

```
